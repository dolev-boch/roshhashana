# תמונות מוצרים

## איך הקוד יודע איזו תמונה שייכת לאיזה מוצר

**לפי שם הקובץ.** הכלל היחיד: שם הקובץ = מזהה המוצר (`id`) שב-`js/data/products.js`.

```
assets/images/products/honey-almond-cake.jpg   ->  המוצר שה-id שלו honey-almond-cake
```

שומרים קובץ בשם הנכון, עושים `git push`, והוא מופיע. אין צורך לגעת בקוד.

אפשר גם לציין נתיב מפורש בשדה `image` של המוצר, והוא יגבר על שם הקובץ.
זה שימושי לתמונה מ-Cloudinary או לקובץ בשם אחר.

> **למה לא זיהוי אוטומטי לפי סדר או לפי כל קובץ בתיקייה?**
> האתר סטטי, בלי שרת, ו-JavaScript בדפדפן אינו יכול לקרוא רשימת קבצים
> מתיקייה. לכן ההתאמה חייבת להיות לפי שם — או לפי נתיב שנכתב מראש.

## למה לא להשאיר שמות בעברית

הקוד תומך בשמות בעברית — הוא מקודד אותם אוטומטית לכתובת תקינה. אבל לא כדאי,
משלוש סיבות מעשיות:

1. **סיומת באותיות גדולות.** הקבצים שלכם הם `.JPG`. שרתי Vercel רגישים
   לאותיות רישיות, ולכן `cake.jpg` ו-`cake.JPG` הם שני קבצים שונים.
   זו תקלה שקשה לאתר, כי במחשב Windows הכול נראה תקין.
2. **git ורווחים.** git מציג שמות שאינם באנגלית כרצף מספרים, ורווחים
   בשמות מסבכים כל פקודה בשורת הפקודה.
3. **הכתובת באתר** הופכת ל-`%D7%A2%D7%95%D7%92%D7%AA%20...` — עובד, אך
   בלתי קריא כשמנסים לאתר תקלה.

### שינוי שם אוטומטי

בשורש הפרויקט, ב-Git Bash:

```bash
bash tools/rename-product-images.sh
```

הסקריפט משנה את שמות הקבצים בעברית לשמות הנכונים, מזהה כל סיומת
(`.JPG`, `.jpg`, `.jpeg`, `.png`, `.webp`), ומדלג על קובץ שכבר קיים.
הוא אינו מוחק דבר.

## מה לצלם ואיך לייצא

| מה | ערך |
|---|---|
| יחס | **4:5 לגובה** — זה מה שהקוד מצפה לו |
| מידות | 800×1000 פיקסלים |
| משקל | עד 150KB לקובץ |
| פורמט | JPG, או WebP למשקל קטן יותר |

**גודל הפיקסלים אינו משנה** — הדפדפן מקטין לבד. מה שכן משנה הוא **היחס**.
תמונות בגדלים שונים ייראו זהות באתר, כל עוד כולן ביחס 4:5.

עשרת הצילומים הקיימים כבר נחתכו ליחס הזה ומוכנים לשימוש. הצילומים
המקוריים היו לגובה, ונחתכו ידנית כך שהמוצר ממורכז בפריים.

מומלץ להשאיר מעט מרווח סביב העוגה בצילום, ולא למלא את הפריים עד הקצה.

## איך הקוד מבטיח שהמוצר נראה כמו שצריך

### 1. יחס התיבה זהה ליחס הקבצים
תיבת התמונה מוגדרת ב-`--media-ratio: 4 / 5` (בקובץ `css/tokens.css`),
והקבצים עצמם נשמרו ב-800×1000 — בדיוק אותו יחס.

התמונה מוצגת ברוחב 250px לכל היותר, ולכן 800px נותנים חדות מלאה גם במסך
Retina. המסגרת מצוירת ב-`box-shadow` ולא ב-`padding`, כדי שהיחס יישאר
מדויק והדפדפן ימשיך שלא לחתוך דבר.

**המשמעות: הדפדפן אינו חותך דבר.** החיתוך נעשה מראש בעריכה, בבחירה ידנית
של הפריים לכל צילום, ולכן המוצר נראה בדיוק כפי שנבחר — בכל מסך ובכל רוחב.
אין תרחיש שבו הדפדפן יקצץ את ראש העוגה.

### 2. אף פעם אין מתיחה
נעשה שימוש ב-`object-fit: cover` ולא במתיחה לגודל התיבה. תמונה לעולם
לא תיראה רזה או שמנה, בשום רוחב מסך.

### 3. הפריסה לא קופצת
לכל תמונה יש `width` ו-`height` מוצהרים ביחס 1:1. הדפדפן שומר את המקום
עוד לפני שהקובץ ירד, ולכן הטקסט לא קופץ בזמן הגלילה.

### 4. הרספונסיביות
- **נייד:** התמונה תופסת את מלוא רוחב העמודה, מעל הטקסט.
- **מסך רחב:** עמודה ריבועית של 268 פיקסלים לצד הטקסט.

התיבה תמיד ריבועית, בכל רוחב מסך. אין רוחב שבו התמונה מתעוותת.

### 5. תמונה חסרה או שבורה
אם קובץ לא נמצא, מוצג במקומו סימן המותג במקום ריבוע שבור.

## אם תמונה מסוימת אינה ריבועית

יש שתי בקרות בקובץ `js/data/products.js`, לכל מוצר בנפרד:

**`fit: 'contain'`** — התמונה כולה נכנסת לתיבה, בלי שום חיתוך.
נוצרים שוליים בצדדים, בצבע רקע שנראה מכוון. מתאים לצילום מוצר על רקע לבן.

```js
{
  id: 'tall-cake',
  image: 'assets/images/products/tall-cake.jpg',
  fit: 'contain',
}
```

**`focus`** — נקודת העניין, כשהחיתוך מקצץ את החלק הלא נכון.
מקבל `'top'`, `'bottom'`, `'center'` או ערך CSS מלא כמו `'50% 30%'`.

```js
{
  id: 'layer-cake',
  image: 'assets/images/products/layer-cake.jpg',
  focus: 'top',   // שומר על החלק העליון של העוגה
}
```

## מתי Cloudinary כן שווה את זה

Cloudinary מוסיף דבר אחד: יצירה אוטומטית של ארבע גרסאות בגדלים שונים
(`srcset`), כך שטלפון מוריד קובץ קטן ומסך גדול מקבל קובץ חד. לקובץ מקומי
זה לא קורה — כולם מקבלים את אותו קובץ.

עם עשר תמונות של 300KB זה הבדל שקשה להרגיש. אם יתווספו הרבה מוצרים,
או אם התמונות כבדות, אז זה מתחיל להשתלם.

**שימוש:** מדביקים את הכתובת המלאה מ-Cloudinary בשדה `image`. האופטימיזציה
(`f_auto,q_auto`) והחיתוך הריבועי נוספים אוטומטית.

```js
image: 'https://res.cloudinary.com/YOUR_CLOUD/image/upload/v1/zuza/honey-cake.jpg',
```

לחלופין, מגדירים פעם אחת ב-`js/config.js`:

```js
cloudinaryBase: 'https://res.cloudinary.com/YOUR_CLOUD/image/upload',
```

ואז מספיק לכתוב במוצר `image: 'zuza/honey-cake'`.

ל-Cloudinary יש יתרון נוסף: `g_auto` בטרנספורמציה מזהה את נושא התמונה
וחותך סביבו, ולא סביב המרכז הגאומטרי. כך גם תמונה שאינה ריבועית נחתכת
במקום הנכון, בלי התערבות ידנית.

**שתי הדרכים יכולות לחיות זו לצד זו** — חלק מהמוצרים עם קובץ מקומי
וחלק עם Cloudinary. הקוד מזהה לבד לפי הערך בשדה.
