# זוזה פטיסרי — אתר הזמנות לראש השנה 2026

אתר סטטי (HTML / CSS / JavaScript בלבד, ללא תלויות חיצוניות) המיועד לאירוח ב‑Vercel.
בנוי בעברית מלאה, RTL, ומותאם לדסקטופ ולנייד — Chrome, Safari (iPhone), Samsung Internet.

---

## הפעלה מקומית

```bash
npx serve .        # ואז http://localhost:3000
```

חשוב: יש לפתוח דרך שרת ולא בלחיצה כפולה על `index.html`.
הקוד בנוי ממודולי ES, ודפדפנים חוסמים אותם בפרוטוקול `file://`.

## פריסה ל‑Vercel

### דרך א׳ — GitHub (מומלץ)

1. העלו את התיקייה לריפוזיטורי ב‑GitHub.
2. ב‑Vercel: **Add New → Project → Import** את הריפו.
3. בהגדרות הבנייה:
   - Framework Preset: **Other**
   - Build Command: להשאיר ריק
   - Output Directory: להשאיר ריק (שורש הפרויקט)
4. **Deploy**. כל `git push` יפרוס גרסה חדשה אוטומטית.

### דרך ב׳ — מהמחשב

```bash
npm i -g vercel
vercel          # תצוגה מקדימה
vercel --prod   # לייב
```

### דומיין

Vercel → Project → Settings → Domains → הוספת הדומיין ועדכון רשומות ה‑DNS.
לאחר מכן יש לעדכן ב‑`index.html` את `<link rel="canonical">` ואת `og:image`,
וב‑`robots.txt` את כתובת ה‑sitemap.

## עדכונים שוטפים

כל התוכן והמדיניות מרוכזים בשני קבצים. אין צורך לגעת בקוד אחר.

### 1. `js/data/products.js` — התפריט

הוספת מוצר:

```js
{
  id: 'chocolate-tart',                          // מזהה ייחודי, לא לשנות אחרי פרסום
  category: 'centerpiece',                        // מזהה קטגוריה קיים
  name: 'טארט שוקולד',
  desc: 'תיאור קצר.',
  price: 130,                                     // מספר בלבד
  image: 'assets/images/products/tart.jpg',
  note: 'קוטר 22',                                 // רשות
  badge: 'חדש',                                    // רשות
  available: true,                                 // false יציג "אזל מהמלאי"
}
```

- **שינוי מחיר** — עדכון השדה `price`. הסכומים בעגלה מתעדכנים לבד.
- **הסרת מוצר** — מחיקת האובייקט, או `available: false` כדי להשאירו מוצג כאזל.
- **קטגוריה חדשה** — הוספה למערך `CATEGORIES` ושימוש ב‑`id` שלה במוצרים.

### 2. `js/config.js` — פרטי העסק ומדיניות ההזמנות

| הגדרה | משמעות |
|---|---|
| `business.phone` / `whatsapp` | טלפון ומספר וואטסאפ בפורמט בינלאומי (`972` + המספר בלי ה‑0) |
| `campaign.ordersCloseOn` | תאריך אחרון לקליטת הזמנות |
| `pickup.startDate` / `endDate` | חלון תאריכי האיסוף |
| `pickup.leadTimeHours` | זמן הכנה מינימלי (כרגע 48 שעות) |
| `pickup.closedWeekdays` | ימים סגורים. `[6]` = שבת, `[5, 6]` = שישי ושבת |
| `pickup.closedDates` | תאריכים בודדים שסגורים, למשל `['2026-09-07']` |
| `pickup.slots` | שעות איסוף לפי יום בשבוע |
| `pickup.slotsByDate` | חריגה לתאריך מסוים (כרגע: ערב החג עד 11:00) |
| `ui.maxQtyPerItem` | כמות מרבית לפריט |

הלוח, הכפתורים והטקסטים באתר נגזרים מההגדרות האלה אוטומטית.

## תמונות מוצרים

לכל מוצר יש שדה `image`. כרגע כולם ריקים, ולכן מוצגת תמונת ברירת מחדל מותגית.
שלוש דרכים למלא אותו:

**א׳ — קובץ מקומי (הכי פשוט)**
שמירת הקובץ ב‑`assets/images/products/` ואז:
```js
image: 'assets/images/products/honey-cake.jpg',
```
הקובץ נפרס עם האתר ל‑Vercel.

**ב׳ — כתובת מלאה מ‑Cloudinary או כל CDN**
```js
image: 'https://res.cloudinary.com/demo/image/upload/v1/zuza/honey-cake.jpg',
```
לכתובות Cloudinary מוזרקת אוטומטית אופטימיזציה (`f_auto,q_auto`).

**ג׳ — Cloudinary עם הגדרה חד־פעמית**
ב‑`js/config.js`:
```js
cloudinaryBase: 'https://res.cloudinary.com/YOUR_CLOUD/image/upload',
```
ואז מספיק לכתוב במוצר `image: 'zuza/honey-cake'`.

מפרט מומלץ: יחס 4:3, רוחב 1200px, עד 300KB, JPG או WebP.
אם תמונה חסרה או נכשלת — מוצג ה‑placeholder במקומה, בלי תמונה שבורה.

## נגישות

האתר כולל תפריט נגישות צף, בהתאם לתקנות שוויון זכויות לאנשים עם מוגבלות
(התאמות נגישות לשירות) ולתקן ת"י 5568.

**התאמות זמינות:** הגדלת טקסט בארבע דרגות, ניגודיות גבוהה, ניגודיות בהירה,

והדגשת מיקוד. ההעדפות נשמרות בדפדפן וחלות אוטומטית בביקור הבא.

הכפתור צף בצד ימין, אינו מכסה תוכן, ובנייד הפאנל נצמד לתחתית המסך.

**חשוב להבין:** תפריט נגישות אינו הופך אתר לנגיש. הנגישות עצמה בנויה בתוך

תקנית בכל הטקסטים, תוויות ARIA, וטקסט חלופי. התפריט מוסיף שכבת התאמה מעליה.

### מה שנשאר לכם להשלים

הקובץ `accessibility.html` הוא הצהרת הנגישות, כנדרש בתקנות. **יש להשלים בו

## שפת העיצוב

האתר מצטט את התפריט המודפס של הקונדיטוריה, ולא תבנית ממשק כללית:

- **נייר שמנת ומסגרת זהב** — קו שיער בודד ממסגר את החלון (`.page-frame`), בדיוק כמו המסגרת בתפריט המודפס. ל-Hero יש מסגרת פנימית משלו על הרקע הירוק.
- **רשימת מנות, לא רשת כרטיסים** — עמודה אחת ברוחב 880px. שם המנה בצד אחד, המחיר בשני, קו נקודות מחבר ביניהם, ומפריד מנוקד בין המנות. זה המבנה של תפריט, לא של חנות.
- **קווי שיער במקום צללים** — `--shadow-sm` ו-`--shadow` מוגדרים כ-`none`. עומק נוצר מקווים ומרווח.
- **פינות כמעט ישרות** — `--radius: 2px`. אין כפתורי גלולה ואין כרטיסים מעוגלים.
- **מעוין הזהב** כמפריד חוזר: בקווי הכותרות, ברצועת המידע ובמחוון הטעינה.

## מחוון הטעינה

אות אחת נראית בכל רגע, והאותיות רצות ברצף **Z ואז U ואז Z ואז A**, בלולאה.
המילה המלאה לעולם אינה מוצגת יחד, והרצף זהה בכל רענון.

הרצף מונע ב-CSS (`@keyframes letter-run` עם השהיות מדורגות), כי אנימציית CSS רצה
על ה-GPU ואינה נעצרת כשהדפדפן עסוק בפענוח משאבים — בדיוק הרגע שבו מסך הטעינה מוצג.

**שני כללי תאימות שחשוב לא לשבור בעריכה:**

1. **אין `var()` ואין `calc()` בשום מאפיין `animation`.** ספארי נופל על צירוף כזה,
   וכשהוא נופל כל ההצהרה מתאפסת והאותיות קופאות על הראשונה. הזמנים כתובים כערכים
   מפורשים: משך 2.2s והשהיות 0s / 0.55s / 1.1s / 1.65s. לשינוי הקצב יש לעדכן את
   כולם יחד. יש בדיקה אוטומטית שנכשלת אם מישהו מחזיר `var()` לשם.
2. **שימוש ב-longhand ולא ב-shorthand** (`animation-name`, `animation-duration`...),
   כדי שכשל בהצהרה אחת לא יבטל את השאר.

3. **חפיפה של 3% בין אות לאות.** האות יוצאת ב-28% והבאה נכנסת ב-25%. בלי החפיפה
   נוצר רגע שבו אף אות אינה מוצגת, והמחוון נראה מהבהב או שבור.
4. **המיכל גדול מהאות ו-`overflow: visible`.** Yellowtail הוא כתב קליגרפי
   שהקישוטים שלו חורגים מתיבת הגופן; מיכל צמוד חתך את ראש ה-Z.

**מנגנון גיבוי:** המודול מאזין ל-`animationstart`. אם האנימציה לא התחילה תוך 400ms —
למשל כשאנימציות חסומות בהגדרות הדפדפן או במצב חיסכון בסוללה — הוא מוסיף `is-js`
ומניע את הרצף בעצמו. המיקום ברצף מחושב מהזמן שחלף בפועל ולא מספירת פעימות,
ולכן דפדפן עמוס יגרום לדילוג על אות ולא לתקיעה על אות.

**הפחתת תנועה:** הרצף נשמר, אבל ההחלפה היא הצללה בלבד ללא הזזה, ובקצב איטי יותר.
מחוון טעינה שאינו זז אינו מחוון טעינה.

| מה לשנות | איפה |
|---|---|
| קצב ההחלפה | ארבע ההשהיות ו-`animation-duration` ב-`css/components.css`, וכן `STEP_MS` ב-`js/ui/preloader.js` |
| משך מינימלי של מסך הפתיחה | `ui.minPreloaderMs` ב-`js/config.js` (2200ms = מחזור מלא) |

## מלכודת שחוזרת — transform ו-filter

אלמנט בעל `transform` או `filter` הופך ל-**containing block** עבור צאצאים
במיקום `fixed`. במילים אחרות, `position: fixed` בתוכו מתמקם ביחס אליו
ולא ביחס לחלון.

זה כבר הפיל את הפרויקט פעם אחת: לעטיפת תפריט הנגישות היה `transform`,
והפאנל שבתוכה מוקם ביחס לכפתור בגודל 46px — ולכן נראה מעוות וחתוך בנייד.

לכן: העטיפה `.a11y-widget` היא `position: static` וללא `transform`, והמרכוז
האנכי נעשה ב-`margin-block-start` שלילי. מאותה סיבה גם ההתאמה "גווני אפור"
מחילה `filter` על תמונות בלבד ולא על `<html>` — אחרת הכותרת הדביקה וסרגל
ההזמנה היו נשברים. יש בדיקה אוטומטית שסורקת את כל ה-CSS ומתריעה על מקרה כזה.

המקור מול יעד התמיכה: **Chrome אנדרואיד 90+ · Safari iOS 14+ · Samsung Internet 14+ ·
Edge/Chrome/Firefox דסקטופ**. כל יכולת מודרנית שנעשה בה שימוש היא או בתוך יעד
התמיכה, או עטופה ב-`@supports` עם נפילה, או שיפור בלבד שאפשר להתעלם ממנו.

- **iOS Safari** — שדות ב‑16px (מונע זום בהתמקדות), נעילת גלילה בשיטת `position: fixed`, `-webkit-backdrop-filter`, `dvh` עם נפילה ל‑`--vh` המחושב ב‑JS.
- **Samsung Internet** — `color-scheme: light` ו‑`theme-color` מונעים היפוך צבעים אוטומטי.
- **Chrome אנדרואיד** — `touch-action: manipulation` (ביטול השהיית 300ms), `overscroll-behavior` נגד רענון‑במשיכה מיותר.
- **מכשירים עם חריץ** — `viewport-fit=cover` ו‑`env(safe-area-inset-*)` בכל הרכיבים הצמודים לקצוות.
- **נגישות** — ניווט מקלדת מלא כולל בלוח השנה (חיצים), מלכודת פוקוס בדיאלוגים, `aria-live` להודעות, יעדי מגע של 44px לפחות, כיבוד `prefers-reduced-motion`, וקישור דילוג לתוכן.
- **ללא JavaScript** — מוצגת הודעה עם מספר הטלפון, ומסך הטעינה אינו חוסם את העמוד.
